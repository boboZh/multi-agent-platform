# 多 Agent 可视化工作流搭建平台｜项目总结与简历素材

分析日期：2026-11-10。依据当前工作区代码，包含尚未提交的改动；功能结论来自静态代码分析，测试结果来自本次 Vitest 执行，不代表已完成外部模型、Redis、Supabase 的端到端验证。

## 一、项目定位

面向多步骤 AI 任务的可视化工作流搭建平台，将 Agent 配置、工具接入、流程编排、执行恢复与运行调试整合到统一工作台。用户可以通过拖拽节点组织多个 Agent 和工具，配置数据传递、条件路由、并行处理与人工审核，并在运行控制台查看执行过程。

项目的核心价值是把需要编写 LangGraph 代码的流程转化为可配置、可校验、可发布、可恢复的工作流，让多 Agent 协作从单次对话扩展到具有明确控制流与状态管理的任务执行。

这里的多 Agent 协作主要由用户显式编排，条件节点可选择表达式或 LLM 路由。适合定位为 AI 应用工程 / 全栈工程项目。

## 二、已实现的主要功能

### 1. Agent 管理与独立试运行

- 管理 Agent 的名称、系统提示词、模型、温度和绑定工具。
- 统一适配 OpenAI、DeepSeek、Anthropic、Google 模型调用。
- 基于 LangGraph `createReactAgent` 实现模型与工具的 ReAct 执行循环。
- 支持流式聊天、会话列表、历史记录及会话配置快照；聊天检查点使用 Redis。
- 对较早对话生成摘要，保留最近两轮消息参与后续推理，控制长对话输入规模。

### 2. 可配置工具接入

- 提供工具管理界面，按配置构造 LangChain Tool 及 Zod 参数约束。
- 支持 HTTP 请求和静态 JSON 模板执行器，包括参数映射、请求构造、响应字段提取与超时处理。
- 同一工具既可由 Agent 自主调用，也可作为独立工作流节点执行。
- 部分旧工具采用名称匹配执行，部分示例返回模拟数据；不宜把全部工具描述为真实业务系统集成。

### 3. 可视化工作流编辑

- 基于 React Flow 实现节点拖拽、连线、属性编辑、缩略图和校验错误定位。
- 支持 9 类节点：开始、结束、Agent、工具、条件、人工审核、Fork、Join、赋值。
- 通过开始节点声明运行参数，通过 `inputMap` 读取上游状态，通过 `outputKey` 写入变量。
- 支持表达式 / LLM 条件分支、串行执行、受约束的并行执行，以及条件回边与赋值节点组成的循环。
- 区分草稿保存、图结构校验和编译校验，允许保存尚未连完或配置不全的流程。

### 4. DSL 编译与版本发布

- 使用 TypeScript 与 Zod 定义统一工作流文档，贯通画布、存储、校验与执行。
- 校验节点及边的唯一性、端口连接、资源引用、可达性、结束路径及并行区域规则。
- 将 DSL 转换为 LangGraph `StateGraph`，注册节点处理器、普通边、条件边和并行汇合屏障。
- 发布前执行 dry-run 编译，成功后保存 `flow_versions` 快照；运行绑定具体流程版本，编辑草稿不会改变该运行所使用的 DSL。

### 5. 执行、恢复与运行控制台

- 运行接口创建任务后通过 Next.js `after()` 调度执行；SSE 接口独立订阅运行事件。
- 工作流状态检查点写入 PostgreSQL，支持人工审核挂起、提交表单后继续执行，以及从目标节点执行前的检查点续跑。
- Redis 承担事件缓冲、Pub/Sub 广播及运行锁；关键运行事件持久化到数据库。
- 控制台展示运行列表、状态筛选、节点高亮、事件时间线、节点状态快照和人工审核表单。
- 接入 LangSmith tracing，并附带流程、版本、运行、会话等元数据，便于关联排查。

## 三、最值得强调的技术难点

### 难点 1：让可自由编辑的画布具有严格的执行语义

**问题：** 编辑过程中必然存在缺少连接、尚未选择 Agent、配置未填完等中间状态。如果只用一套严格规则，草稿难以保存；如果规则过松，错误会延迟到模型调用阶段才暴露。

**实现：** 定义 `draft / graph / compile` 三档校验，逐步增加结构与可执行性约束；错误携带 `path / nodeId / edgeId`，供编辑器定位。编译前集中解析 Agent 与工具引用，再构造 LangGraph 执行图。

**简历价值：** 体现 DSL 设计、图结构校验与前后端契约设计能力。

### 难点 2：并行分支正确汇合与共享状态隔离

**问题：** 两条分支长度不同时，Join 必须等待所有通道完成；多个 Agent 同时写消息和同名变量时，容易发生结果覆盖或上下文串扰。

**实现：** 静态遍历 Fork 各通道，推断唯一配对 Join，校验通道独立性与实际链尾；将全部链尾编译为 LangGraph 数组前驱屏障。并行区域中的 Agent / Tool 不回写共享 `messages / lastAgentText`，结果写入独立 `vars` 槽，并在编译期检测写入冲突。屏障前驱排序，保持重复编译时的通道命名稳定，便于匹配检查点。

**边界：** 当前支持 2～16 条通道；通道内部仅允许 Agent、工具和赋值节点，不支持嵌套 Fork、条件节点或人工审核。

**简历价值：** 体现并发控制、状态合并、图分析和执行语义设计能力，是项目最有辨识度的技术点之一。

### 难点 3：人工介入和失败后的状态恢复

**问题：** 审核可能跨越多次 HTTP 请求；失败后从头执行会重复上游模型和工具调用，并丢失已有状态。

**实现：** 工作流使用 PostgreSQL checkpointer，按 `thread_id` 保存执行状态；人工审核节点调用 `interrupt()`，恢复时提交 `Command({ resume })`。节点重试从状态历史寻找目标节点即将执行的检查点，在同一 thread 下指定 `checkpoint_id` 续跑。

**边界：** 检查点续跑不等于外部工具副作用的 exactly-once 保证；回退后可能重新执行目标节点及后续节点，并行场景也可能涉及同一执行步中的其他任务。

**简历价值：** 体现持久化状态机、Human-in-the-loop 和失败恢复设计能力。

### 难点 4：执行与实时展示解耦后的事件一致性

**问题：** 页面刷新或网络断开后，既不能重新触发工作流，也不能简单丢弃已产生的运行事件；历史回放切换到实时订阅时还存在漏帧窗口。

**实现：** 执行引擎独立产生事件，SSE 路由仅负责订阅。Redis Lua 原子执行事件序号分配、追加缓冲和广播；客户端以 `Last-Event-ID / after` 游标续接。服务端历史回放后建立订阅，再补扫缓冲，并在保活期间补拉；通过序号过滤重复帧。缓冲设置裁剪与过期，关键事件另行落库。

**边界：** Redis 缓冲过期后，数据库只能回放关键事件，不能保证恢复完整 token 流；`after()` 执行仍受部署平台单次函数时限约束，当前没有独立持久任务队列。

**简历价值：** 体现 SSE、Redis 原子操作、断线恢复与异步系统设计能力。

### 难点 5：画布状态与文档状态保持一致

**问题：** 编辑器同时维护画布数据和业务文档时，容易出现拖拽回弹、保存位置不一致；React Flow 自动产生的尺寸和选中变化还会误触发“未保存”状态。

**实现：** 直接使用兼容 React Flow 结构的 `WorkflowDocument` 作为单一数据源；把选中、尺寸测量等变更标记为 transient，避免误标脏；统一处理开始节点保护和节点删除时的关联边清理。

**简历价值：** 体现复杂交互编辑器的数据建模和状态治理能力。可以描述具体机制，暂不填写没有实测的渲染性能提升比例。

## 四、可直接放入简历的版本

### 通用版：AI 应用 / 全栈岗位

**项目名称：多 Agent 可视化工作流搭建平台**

**技术栈：** Next.js 16、React 19、TypeScript、React Flow、Zustand、LangGraph / LangChain、Zod、Supabase / PostgreSQL、Redis、SSE、Vitest。

**项目描述：** 面向多步骤 AI 任务构建可视化工作流平台，支持 Agent 与工具配置、流程编排、版本发布、人工审核及运行调试，打通从图形化配置到 LangGraph 执行与状态恢复的完整链路。

- 基于 React Flow 与统一工作流 DSL 实现 9 类节点编排，支持变量映射、表达式 / LLM 条件路由及草稿、图结构、编译三级校验，将画布配置转换为 LangGraph 执行图。
- 实现 Fork–Join 并行区域分析与汇合屏障，通过通道独立性校验、并行上下文隔离和变量写入冲突检测，支持 2～16 路任务并行及结果汇聚。
- 基于 PostgreSQL 检查点实现人工审核中断恢复与节点执行前状态回退，结合发布版本快照管理流程定义与运行状态。
- 解耦工作流执行与 SSE 订阅，利用 Redis Lua、Pub/Sub 和游标缓冲回放实现事件广播、重连补帧与去重，联动节点高亮、事件时间线及状态快照辅助调试。
- 统一封装多模型与 HTTP 工具接入，基于 ReAct 实现工具调用，结合近期消息窗口与历史摘要管理对话上下文；现有 Vitest 测试覆盖 DSL、并行编排、恢复逻辑与事件处理等核心模块。

基于 Next.js、React Flow 与 LangGraph 构建多 Agent 可视化工作流平台，支持 9 类节点、条件路由、并行汇合、版本发布与运行调试。设计统一 DSL 及分级校验，将画布编译为可执行状态图；通过并行区域分析和状态隔离处理多分支汇合与写入冲突；基于 PostgreSQL 检查点实现人工审核恢复和节点重试，并使用 Redis + SSE 实现执行事件推送与断线补帧。

## 五、面试时的一分钟项目介绍

这个项目是一个多 Agent 可视化工作流搭建平台，用户可以先配置 Agent 的模型、提示词和工具，再在画布中把它们连接成包含条件分支、并行处理和人工审核的任务流程。

核心是把画布文档定义成统一 DSL，通过分级校验后编译成 LangGraph 状态图。比较复杂的是并行和恢复：并行时需要识别每条通道的链尾，确保 Join 等齐所有分支，同时隔离消息和输出变量；人工审核和失败重试则依赖 PostgreSQL 检查点，在同一会话中恢复执行。运行展示通过 Redis 和 SSE 与执行解耦，页面重连时按事件游标补帧，控制台可以查看节点状态和执行时间线。

## 七、主要代码依据

- `lib/workflow-dsl/schema.ts`：工作流结构、节点配置与分级校验。
- `lib/workflow-dsl/compile.ts`、`compile-utils.ts`：状态图编译、变量映射、节点执行和路由。
- `lib/workflow-dsl/fork-join-regions.ts`：并行区域分析、通道约束和写入冲突检测。
- `app/(dashboard)/workflows/components/workflow-canvas.tsx`：画布单一数据源及 transient 变更处理。
- `app/api/workflow/publish/route.ts`：编译校验和发布快照。
- `lib/workflow-runtime/engine.ts`、`runner.ts`：执行调度、流式事件和运行状态处理。
- `lib/workflow-runtime/checkpointer.ts`、`retry.ts`：PostgreSQL 检查点和重试快照选择。
- `lib/workflow-runtime/buffer.ts`、`app/api/workflow/runs/[id]/events/route.ts`：事件原子追加、广播和 SSE 补帧。
- `app/(dashboard)/runs/`：运行列表、状态展示、事件时间线和审核交互。
- `app/api/chat/route.ts`、`lib/agent-runtime/`：Agent 试运行、工具调用与上下文摘要。
- `lib/langsmith/tracing.ts`：链路元数据及 trace 刷新。
